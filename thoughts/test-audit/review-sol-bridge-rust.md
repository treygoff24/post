## Product bugs and caller checks

- **S1 confirmed by source; runtime unverified.** On a first delivery with no live admission record, `decide` calls `admission_checks` before writing the D1 record (`src/commands/bridge.rs:183-235`). That function checks the sender placeholder first (`:341-364`), then calls `participant::revive_locked` (`:365-385`), then checks room/rules and can return `blocked_route` (`:387-404`). `revive_locked` moves an archived participant into the live directory via `gc::restore` before returning (`src/participant.rs:576-595`). Thus an otherwise valid letter addressed to a GC-archived recipient, with a blocking rule for the route, receives a terminal **rejected/blocked_route** decision yet restores the participant under the same id, including its archived state. The recipient reappears in the live participant registry, though its lease may remain stale; no admission record, inbox letter or routing receipt is created for this letter. A direct retry for the same refused letter now sees the revived recipient. The ended check is also after revival (`src/commands/bridge.rs:378-383`): a stored archived record with `ended_at` set would be restored then rejected `ended_participant`. This is reachable through GC once an ended stateful participant ages past its archive window (`src/participant.rs:156-159`; `src/commands/participant_gc.rs:251-297,300-308`), but the blocked-route case alone establishes S1. `a_refused_letter_does_not_restore_an_archived_recipient` checks only earlier `forged_from` (`tests/bridge_deliver.rs:1101-1115`); the existing blocked-route test uses a live session-only recipient (`:1118-1141`). Add a separate product-regression test using `archive_recipient(&rig)` (`:1009-1035`), a wildcard blocked rule like `:1121-1124`, and a valid new letter. Snapshot **after** rule creation; assert `rejected/blocked_route`, `replay:false`, archive and state bytes still present, live participant directory absent, and no import/inbox/receipt. This test goes red on the current code at the live/archive-state assertions, then belongs with the product fix. Search used: `rg -n 'admission_checks|revive_locked|ensure_route_allowed|blocked_route|ended_participant' src/commands/bridge.rs src/participant.rs src/commands/send.rs tests/bridge_deliver.rs`.
- **S2 confirmed as a message-classification defect; runtime unverified.** `channel_relay_status` maps every `read_regular` result other than `Ok(Some(bytes))` to `LocalOnly("no bridge config")` (`src/bridge_topology.rs:320-335`), including a present but unreadable or nonregular config. The local-send caller therefore receives an inaccurate reason; this is not a reason to delete either unit test. Search used: `rg -n 'channel_relay_status|read_regular' src/bridge_topology.rs src/commands src`.
