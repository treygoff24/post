## New or repaired assertions: binding check

- GC tombstone field checks use non-default fixture values; mutations dropping `workspace_path` and `ephemeral` turned the restore keeper red. The schema environment assertion parses one `POST_AUTO_GC:` entry and requires the `=0 disables` text; changing it turned red. The auto-GC bookkeeping test compares rooms and doctor `(id,path,severity)` before/after and verifies the files exist; a synthetic doctor check naming `.auto-gc.log` turned it red.
- The lineage consolidated gap count and byte-identical retry can fail for a lost increment or retry rewrite. The over-limit voice assertion turned red under a limit mutation. Its lock keeper binds command-level ordering, but cannot bind the internal `create` lock (same limitation as the deleted test).
- The corrupt canonical mail assertion now requires `config_invalid` plus the offending `.mail` filename and separator reason. Bypassing the reparse returned `not_found` and turned it red.
- Owner locator table now has a genuinely signed valid-tag control. Unknown-version, extra-key and float-version rows can turn true if their parser guard is removed; reported mutations did turn them red. Missing-tag/null/non-object rows distinguish `false` from unsigned `None`. Empty/path-like tags have a direct private-parser test with a valid control; both grammar mutations turned it red. The read-cap fixture has a genuine signed over-cap manifest, and removing the cap turned red. The channel-binding fixture verifies before a checked envelope rewrite and fails after it; removing the envelope-channel guard turned red.
- Migration snapshot now compares the whole store before/after, checks actual participant heartbeat/cursor paths, then checks both bytes and mtime of a pre-seeded aged heartbeat. Both mint and refresh mutations turned it red. The missing-state/no-lock row has a successful legacy control and an exact migration error; its admission mutation turned red. The duplicate-state row now declares generation 7 and turned red under a duplicate-key visitor mutation. The catchup path carry turned red when Catchup was classified as a reader.

**Binding limits, not lost contracts:** GC's new touch row stays green if only `last_seen` comparison or only `is_active` is removed, because the fresh-age check also keeps the participant; removing all three turns it red. The standalone `last_seen` defense is not independently tested. Lineage's retained CLI lock test remains green if only `create` moves validation above its own lock: dispatch touches the actor under the participants lock before entering `create`. The deleted CLI test had the same blind spot. Neither row should be described as proof of the individual internal guard.

No production executable path or public seam was deleted. The test-only GC hooks, owner hooks, exclusive-write primitive, and admission paths remain because surviving tests and production callers use them.

`src/lineage_store.rs` has no diff: `read_history` and `lineage_journal_ignores_only_a_malformed_final_line` remain. In `src/migration_fence.rs`, `fence`, `activate`, `write_state_locked`, and `transitions_are_locked_and_illegal_transitions_refuse` remain unchanged; the diff touches only the cfg-test read-mode helpers and their test. The maintainer's KEEP rulings were respected.
