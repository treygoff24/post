- Low (consistency): `parse_mail` (mailbox.rs:699-701) reads with `read_to_string`, so a non-UTF-8 `.mail` yields an I/O error ("read mail file", classification `io_error`), while `parse_mail_bytes` (:720) reports the same defect as `config_invalid` ("mail is not UTF-8"). A corrupt inbox file therefore gets a different code depending on entry path. Unverified by execution; I found no test of either non-UTF-8 case.
- Observation, not a bug: the archive namespace is global while inbox namespaces are per-target, and an archive `AlreadyExists` after inbox publication cannot retry (S4 pins that as designed). A cross-room id collision (same second, same 24-bit suffix) would report `delivered_unarchived` although a fresh id would have worked; probability is negligible (about 1 in 16M per same-second pair).
