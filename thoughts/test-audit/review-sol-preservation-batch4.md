## Findings and assertions that do not bind independently

1. **Release binary resolution can be unstable (merge condition).** `cargoReleaseBin` runs `cargo metadata` on every call (`scripts/cargo-release-bin.mjs`). The three new hook-suite defaults each call it at module load; `launcher/agent-session.test.mjs` calls it separately, and Codex's real-binary row calls the CLI again. The lane proof log observed different managed target slots and about a hundred `ENOENT` failures until `POST_BIN` was pinned. `gate.sh` exports one `POST_BIN` for hook suites, which protects those suites from per-file drift, but its metadata call is separate from its preceding build. `acceptance.sh` also builds and then resolves in a separate invocation. Verify that build and test refer to the same executable rather than relying on two metadata answers to agree.
2. **Bridge author proof was lost (merge condition).** The removed `test_each_branch_reflog_contains_only_its_owner_commits` checked authors across `fc`, `trey`, and `mac` branch reflogs. The surviving `test_tick_commit_has_explicit_identity_without_git_configuration` checks only `fc`. The fixture's pre-receive hook (`bridge/tests/test_sweep.py:525-541`) checks that the actor pushes only its own branch; it never reads commit authors. Thus `trey` or `mac` could start writing a wrong author while all remaining tests pass. Restore the original test or extend the explicit-identity keeper to run a real tick for each host, inspect each produced commit's author, and red-prove a wrong-author mutation for at least the newly covered hosts.
3. **A final Rust no-fallback inbox assertion is redundant.** `a_host_qualified_address_never_falls_back_to_a_workspace` now looks under `rig.root()/pact/inbox`, the correct store path. Its earlier `assert_queued` whole-tree comparison would already fail if remote send wrote that inbox. The lane's injected stray-inbox mutation went red there, before the final assertion. The final assertion is a correct path check but has no demonstrated independent binding; do not count it as a second proof. The unique no-`outbox/` directory check did move to `a_remote_send_writes_only_the_archive_and_reports_queued_in_json_and_text` and its mutation failed specifically there.
4. **The bind-failure table binds the combined predicate, not each branch.** The skill-hook proof log reports that making `boundParticipantId` always succeed went red, but removing only its `ok`/`status` guard or only its id check stayed green because another guard rejected the same fixture. The moved table still protects failed binding as a whole; individual guard coverage is unproven. No deleted row had a stronger independent proof of those individual guards.
5. **Channel first-origin competition remains unproved.** Deleting the two `import_channels.__doc__` greps loses no executable proof: a docstring could stay unchanged while behavior regressed. `test_origin_adopts_once_and_never_changes_created_fields` checks later local edits, and `test_unpublished_sender_quarantine_is_final_across_ticks` checks quarantine finality. Neither puts competing first valid channel records from two hosts through import. This is a pre-existing behavior-level gap, not a justification for keeping the greps; add a two-host first-origin row separately if that rule must be enforced.

## Product changes

- **Rust bridge: approved with a dual-fault caveat.** `decide` takes `participant::lock` before both `admission_checks` and the subsequent admission write; the binding lives through the route and inbox work. `peek_locked` validates the live record, archived record, or reconstructed tombstone without moving it. Forged sender, unknown/unreadable record, ended participant, topology, rules, blocked route, and final revive remain in that order. `ensure_workspaces_route_allowed` is the old rule predicate/error constructor moved behind `ensure_route_allowed`; the send path still loads rules, resolves recipients, gathers their workspaces and runs the same helper, including the lineage early return. For a valid route, a revive failure still maps to `participant_unreadable` and no admission write. A blocked route or ended archived record now refuses without revival, as intended. On simultaneous invalid rules and failed restore/write-index, the new order may report the route/config failure where the old code reported `participant_unreadable`; the literal *dual-fault precedence* is not byte-identical. No ordinary send-path bytes or error codes changed. The new code does not make `revive_locked` atomic: a failure after an archived move or tombstone directory creation can still leave partial revival, a pre-existing limitation outside this fix.
- **Relay-status reason:** A missing config remains `no bridge config`; a present nonregular/unreadable config now reports `bridge config unusable: <reason>`. The added unit test distinguishes the missing and directory cases and was red before the change per the lane proof. The status remains `LocalOnly`.
- **Gate test:** `run_gate` invokes the inherited real bash by absolute path, avoiding direct execution of a just-written bash shim. The child PATH still puts shims first, and `bridge/tests/run-all.sh` uses `#!/usr/bin/env bash`, so the intended stand-in is exercised later. The timeout test still checks failure, elapsed bound and child cleanup; the passing control remains. The absolute resolution does not defeat the gate behavior under test.
- **Installer and acceptance:** `--help` now prints header lines 2–81, including exit code 7 and the unexpected-phase explanation. The acceptance script uses the Cargo release resolver instead of `target/release/post`; target-slot pinning is still required as stated above. `CONTRIBUTING.md` now names the actual `./scripts/gate.sh`, which runs format, clippy, Rust tests, release build, Node suites, schema and bridge Python tests. Test-only real-smoke fixtures use 50 participants; production smoke still defaults to 2,000 and `tests/scaling.rs` owns the 2,000-participant performance contract.
