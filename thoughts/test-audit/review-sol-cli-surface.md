## Priority finding: two tests inherit the live mailbox root

`schema_describes_seen_set_semantics_not_watermarks` (`tests/cli.rs:12652-12680`) and `doctor_brief_is_human_only_and_conflicts_with_json` (`:12683-12694`) spawn `post_command()` without `Sandbox`. That helper clears identity and a few other variables but **does not set or clear `HOME` or `POST_MAIL_ROOT`** (`tests/common/mod.rs:803-823`). `Context::from_env` uses inherited `POST_MAIL_ROOT` if set; otherwise it selects inherited `$HOME/.claude-mail` (`src/mailbox.rs:129-155`). It is therefore not *unconditionally* the developer's default root, but on an ordinary shell without the override it is.

Both reach mailbox-backed startup before their useful assertion. `commands::execute` creates the context and resolves the participant before its human-only flag guard (`src/commands/mod.rs:43,78-101,212-229`); the helper also sets `POST_PARTICIPANT=test-default`, causing that resolution to look for a record in the selected root (`tests/common/mod.rs:821`, `src/participant.rs:399-429`). `schema` then loads the room registry and owner anchor (`src/commands/schema.rs:29-33`, `src/mailbox.rs:1233-1259`). The doctor conflict can fail early because of a real-root error before it reaches the conflict guard. These two test paths appear read-only under current dispatch (`src/commands/mod.rs:163-168`), but reading private live mail state and making results depend on it is a real test-isolation defect. **Sandbox both first**, even though the later consolidation deletes both declarations; do not leave them runnable against the live root during an intermediate cutover.

## Production-code and contract verdicts

- **Published dead codes, real contract decision.** Exact source search used: `rg -n 'NotYet|CrossedSend|not_yet\(|crossed_send\(|Self::NotYet|Self::CrossedSend|ErrorCode::ALL' src --glob '*.rs'`. `NotYet` has no constructor caller outside its own unused `AppError::not_yet` (`src/error.rs:107,432-439`); `CrossedSend` has no constructor anywhere outside the enum's own mappings (`:109,148-149,177-178,190-204`). Both are still listed in `ErrorCode::ALL` (`:132-158`), which `post schema` serializes into `error_codes` (`src/commands/schema.rs:489-496`). `crossed_send` is also explicitly **reserved** in `CONTRACT.md:1343-1351`; `not_yet` is absent from that prose list but published by schema. Removing either code from `ALL`, removing the enum variants, or changing their exit/retry values changes the machine contract. Maintainer decision and an explicit contract/version/compatibility plan are required before any such removal. `CrossedSend`'s enum comment says send was not delivered (`src/error.rs:108`) and is stale against `CONTRACT.md:1350-1351`; correcting the comment is safe. The hand-maintained 25-entry `ALL` matches the 25 variants today, but a new variant can be omitted without a compile error; an exhaustiveness guard is a product follow-up, not an audit deletion.
- **`InboxOutput` is an unused production export, not a schema entry.** Exact caller searches: `rg -n 'InboxOutput\b' src --glob '*.rs'` returns only its declaration at `src/output.rs:1692`; `rg -n 'InboxOutput\b' tests --glob '*.rs'` finds imports/decode uses in `tests/cli.rs` and `tests/surface.rs` only. The real JSON producer is `InboxOutputV2` (`src/commands/inbox.rs:59-73,174-185`); schema describes its current fields independently (`src/commands/schema.rs:226-239`). Removing the stale public Rust struct does **not** alter `post schema` or the emitted inbox JSON. It does remove a public Rust type, so check external crate/API compatibility before deleting it; move test decoding to a test-local current type or `Value` in the owning areas first. Do not claim the current typed decode proves all inbox fields.
- **Version literal drift is possible by source.** `STORE_VERSION` in `src/commands/version.rs:8`, the schema's `store_version: 2` in `src/commands/schema.rs:501`, and the shape string at `:206` are separately maintained. The sample and schema-surface assertions do not compare these to one another. Decide whether to derive schema fields from the version constant in a separate product change.
- **No production seam is unlocked by this area's four D marks.** `remote_index::BUILDS` is `#[cfg(test)]` and OU14's deterministic cache assertion uses it (`src/output.rs:467,491,2609`); keep it while that proof remains. `verify_against` is still needed by CT1's fenced-copy fixture. The broader public-output/Deserialize surface should be audited separately, not inferred dead from this lane.
