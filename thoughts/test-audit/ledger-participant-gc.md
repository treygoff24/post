## F. Suspected product bugs

- S1 (low): `append_log` on `Err` writes `deleted: []`, `archived: []` even if `apply_plan` had already collected records in earlier batches or earlier in the same batch, because `apply_plan` returns `Err(..)` with `?` and drops its partial `Applied`. The module docs promise "Every id it names comes back with `post participant restore <id>`", but those partially collected ids are not named anywhere (the tombstones still allow `restore <id>` if the operator knows the id). A6 only asserts `deleted == []` for the case where the very first collection fails, so it does not expose this. Unverified by execution.
- S2 (nit): `try_run` writes `.auto-gc.stamp` with `fs::write` (follows symlinks) while the lock and log use `O_NOFOLLOW`. Inconsistent, not tested.
