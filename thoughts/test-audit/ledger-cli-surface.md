## Settlement: the three overlapping schema checks

They are not three copies of one check. They point in different directions, and one of them is an older, weaker draft of another.

| Check | Direction / contract | Strength | Date |
|---|---|---|---|
| contract_samples.rs | producer -> sample file, byte-exact after normalisation. Owns the JSON output values and the sample set. | Strongest for output stability; every field present, typed, enum-valued. | 2026-09-22..28 |
| schema_truth.rs | emitted output -> schema shape (every key at any depth named as a whole word), and `--help` option -> schema usage. Owns "the schema does not lie by omission". | Strongest documentation check (`names` word boundary, nested walk, data-keyed maps exempted explicitly, instrument self-tested). | 2026-09-28 (fc4b870, 5 of 5 red against pre-change source) |
| schema_surface.rs (4 tests) | earlier hand-written versions of the same idea (2026-09-01 `5a54a8a`, 09-06 `35d8c78`, 09-16 `3d4875f`): exact top-level key sets for shapes that have no sample, usage == help for four commands (the only usage-is-subset-of-help direction), exact top-level shape lines, phrase greps. | Documented-field check is `shape.contains(field)`: `count` is satisfied by `mention_count`, `id` by `first_id`, `room` by `rooms`, `own` by `known`. Weaker than schema_truth. | older |

Ruling:
- contract_samples owns output truth; schema_truth owns "schema names every emitted field" for shapes it can reach (every sample, plus live send_json/doctor/who/participant/gc/restore/watch-unbound). Keep both.
- schema_surface keeps only what nothing else proves: exact key sets and documented-field checks for shapes with no sample (catchup, search, chat slice/ack, read budget/slice/ack, catchup budget), the usage == help equality for catchup/search/chat/read, the exact top-level shape lists, the phrase pins. Its documented-field check must go through schema_truth's `undocumented` (move `names`, `documented_keys`, `undocumented`, `DATA_KEYED_MAPS` into `tests/common`), so the two stop disagreeing about what "documented" means (F on S3, S4).
- Drop the blocks the newer checks subsume: inbox and channels live blocks (sample keys equal the asserted key sets exactly: inbox top-level and item, channels top-level), doctor top-level live keys, substring containment for fields already in exact shape lists, the usage-token greps that `usage == help` covers, and `the_schema_declares_the_fields_the_contract_names` (every pair is in a schema_surface exact list or a schema_truth live check; see row ST4).
- Unverified risk in that ruling: routing S3/S4 through the whole-word check may newly fail if a shape omits a word today (a real doc hole, not a test bug). Cannot be settled without a run (open question 1).
