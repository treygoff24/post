## Repaired and new assertion binding

The proof logs show red mutations for oversize heartbeat size guard; real ancestor walk; unbound byte fallback and too-small refusal; both invalid room-name findings; workspace-less sender; plain/hostile unbound marker; snapshot heartbeat and unchanged record; event-wake participant heartbeat; vanished-record unbound error; ten-second heartbeat interval; doctor legacy severity in both states; `seen-by` read-only behavior; regex/case-insensitive grep; closed-stderr banner paths; `chat --message` stdin refusal; help/schema exact option parsing; restore-line text; and whole-document schema matching. The current tests contain the preconditions needed for those assertions, including a valid control invocation before the new piped slice refusal and open-stderr banners before the closed-stderr runs.

Four reported exceptions are correctly scoped:

1. The plain `doctor` after fresh-root `--fix` is redundant today. `--fix` re-runs detection and the prior fix report checks healthy status, so no independent disk-defect mutation reached only the plain invocation. Keep it as the documented two-command bootstrap, without counting it as a separate proof.
2. The moved zero-delivery assertion does test a real negative side effect: it samples destination inbox count before the refused existing-file send and requires zero afterward. The path-recognition mutation fails earlier at exit code, so the proof log does **not** establish that this particular assertion binds. It would fail if a command returned the expected refusal while also writing a delivery; this is a reachable regression shape in the send ordering, not an unreachable assertion.
3. The FIFO writer case is a no-hang check. A reader-less FIFO opened with `O_NONBLOCK` fails with `ENXIO` before the file-type guard; removing that guard stays green. Removing `O_NONBLOCK` would hang, so do not count this case as proof of the `is_file` check. Other symlink/hard-link/permission writer guards have red mutations.
4. Removing `#[serde(default)]` from `Envelope::from_participant` stays green because Serde treats an absent `Option` as `None`. The old-mail CLI test binds on accepting the old envelope through the actual parse path, not on that attribute's presence. The attribute is redundant for this field, not a missing compatibility test.
