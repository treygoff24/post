## Bug and seam verdicts

- **S1, real inconsistency; policy unresolved.** `continue_lineage` calls `validate_name` before taking the lock (`src/lineage_store.rs:347-355`); `create` validates after locking (`:266-273`). `validate_name` rejects a later registered-room collision (`src/lineage.rs:93-121`), whereas `load` validates only a path component (`:64-91`), and `leave`, explicit withdrawal, and routing use that tolerant path (`src/lineage_store.rs:412-439,748-773`; `src/routing.rs:853-864`). An existing lineage can therefore remain addressable while `continue` refuses it. Whether `continue` should allow this is a policy decision; no runtime reproduction ran.
- **S2, real crash window, not established as a product bug.** `withdraw_current_voice` settles the gap before calling `append_warning` (`src/lineage_store.rs:596-601`). A crash in between can leave a settled gap without that journal event. The journal is documented as non-decision input (`docs/PARTICIPANTS.md:43,56`); no exactly-once journal guarantee was found. Record as a limitation, not a cutover fix.
- **Test-only reader seam, confirmed.** Exact caller search: `rg -n 'read_history|JournalEntry|ensure_own_voice|add_voice\(|withdraw_voice\(' src tests bridge`. It found `read_history` only at its definition (`src/lineage_store.rs:659`) and U3 calls (`:1384,1396`); `JournalEntry` also has a production **writer** use (`:1199`). `#[cfg_attr(not(test), allow(dead_code))]` at `:658` confirms the reader is knowingly unused outside tests. The documented promise keeps deletion on hold.
- **Foreign-author guard, real code but unreachable from the CLI.** The same caller search found `add_voice` and `withdraw_voice` production calls only in `src/commands/identity.rs:184,208`, where `author = acting.id` at `:179,205`; `ensure_own_voice` runs in production (`src/lineage_store.rs:448,452,515,518`). It is not dead code, although its rejection branch is test-only reachable under the current CLI.
- **Stale dead-code attributes, confirmed.** Exact caller search: `rg -n '\.members\(|lineage::validate_name' src tests bridge`. It found production uses of `members` in `src/lineage_store.rs:186,226` and `src/routing.rs:857`, and `validate_name` in `src/lineage_store.rs:272,353`. `Member` is used in `LineageView` (`src/lineage_store.rs:60`) and `ShowOutput` (`src/commands/identity.rs:25`). There is no deletion to unlock here.
