# Post 0.10.0 release

Published 2026-10-01 CDT:

- GitHub: https://github.com/treygoff24/post/releases/tag/v0.10.0
- Forgejo: http://devbox.tail94f8e5.ts.net:3000/estate/post/releases/tag/v0.10.0
- Each release has 12 assets: four binary archives, source, five checksum
  sidecars, the aggregate checksum file, and its host's shell installer.
- Both Darwin binaries are Developer ID signed with hardened runtime and
  timestamps. Apple notarization accepted both.
- Linux aarch64 and x86_64 binaries are statically linked musl executables.
- All 12 assets were downloaded from each release and compared byte for byte
  or by SHA256. The public installer installed the exact verified binary on
  macOS arm64 and Linux x86_64. An intentionally corrupted Linux archive was
  rejected before installation. Both installers embed the archive checksums.

## Source and public history

The binaries were built from Forgejo's original `v0.10.0`, commit
`d1143176ec8e460cc38f07131bc8a360676256ac`, and report build `d114317`.

The installed-runtime smoke correction is `500c4ad` on Forgejo main. It changes
only `scripts/smoke-installed.sh`; the Rust source, dependencies, built-in skill,
and bridge source remain identical to the build commit. The original checker
failed four stale assumptions: the capabilities list, JSON stderr, and two
fixtures whose newly-bound participants treated old channel messages as history.
The corrected checker retains its strict NDJSON, read-only, and consumption
proofs and passes against the release binaries on both hosts.

GitHub received one snapshot commit, `7517ea0169c04e2bfb312b84c8ebb3f19759310b`,
on top of its existing main. Its tree equals Forgejo `500c4ad`. New public
commit and tag metadata use Trey's GitHub no-reply address rather than importing
the private author-email history. Forgejo retains its original history and tag;
GitHub's `v0.10.0` points to the public snapshot. These tags intentionally have
different commit identities. Do not force either tag to the other's commit.
The release source tarball is the public snapshot, including the smoke fix.

## Verification

The full gate ran on a fresh Forgejo clone on the devbox:

- Format, Clippy, release build and schema passed.
- Rust: 915 passed, 2 existing ignored.
- Hooks: 537 passed. Launcher: 33 passed.
- Bridge: all 10 suites passed; 369 Python cases, one existing skip.
- Test-runner checks: 4 passed.
- Toolchain: Cargo 1.98.1, Node 26.10.0, Python 3.14.7.
- Both native binaries passed all six install checks, including the real Porch
  launch check, and the complete installed-runtime smoke.
- GitHub CI: pending when this receipt was first written; see live runs for
  public snapshot `7517ea0` before claiming its separate CI is green.

Linux builds ran on the devbox with four workers using cargo-zigbuild 0.23.4
and Zig 0.14.1. Darwin builds ran sequentially on the Mac with two workers and
the Command Line Tools SDK, under Trey's explicit exception to his devbox-only
build rule. The downloaded cargo-dist 0.32.0 matched the project pin; the
installed 0.33.0 did not. No full gate or test suite ran on Trey's Mac.

## Installed state

Mac and trey-agent devbox install the exact release binaries at
`~/.local/bin/post`, with verified backups and updated receipts at
`~/.local/share/post/install-receipt.json`. The receipts explicitly name the
prebuilt release as their source; no third Mac compilation was performed.
Both served skill manifests match all 40 files. Existing watch processes were
left alone.

The Mac's old Porch rejected Post's added `avatar` and `warnings` fields.
Porch's existing fix at `8a44b7b` was built as a wheel on the devbox and installed
on the Mac with Trey's approval. Its launch check now passes. The local Porch
checkout and its unrelated dirty files were preserved.

Both bridge packages now contain the release's Python source and a clean BUILD
record naming `d114317`. Configuration checks passed before and after each
swap; the launchd job and systemd timer were restored. The previous packages
were retained as `~/.local/lib/post-bridge.before-0.10.0-*`.

Other cells were not changed. Live doctor still reports legacy store/profile
warnings; it was not represented as a clean store-health result.
