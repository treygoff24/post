## Shared-root-cause clusters

1. **Input intent is implicit for bare stdin** (`pc2_0dd...`, `pc2_459...`). `post chat` uses the same verb for read and send; stdin alone is not considered send intent. One fail-fast check for redirected stdin on the read branch retires both reports while preserving the explicit `--send` boundary.
2. **The skill, runtime, and bridge contract have separate provenance** (`pc2_79f...`, `pc2_161...`). The skill symlink follows a mutable source tree; the binary is separately installed; the bridge reference assumes a devbox-only checkout path. A versioned contract bundle with a stable path and an install/preflight compatibility check addresses both drift and dead references. Schema equality alone is insufficient for prose instructions, and the compile-time `build_sha` is not a binary fingerprint.
3. **Lease state is exposed as if it described attention** (`pc2_b621...`, and the semantics needed by `pc2_ce416...`). `active` and sigil reservation both derive from participant leases, while attention is message-specific. Keep lease labels and sigil occupancy tied to that same lease predicate; surface `--seen-by` separately instead of treating presence as proof of receipt or reading.
4. **Blocking lock calls have no common deadline policy** (`pc2_1dea...` plus other cursor/registry writers). The immediately reachable send wait is the post-commit cursor marker. A shared bounded-lock helper could prevent similar indefinite waits elsewhere, but each caller needs a correct timeout outcome; committed sends must still report success with a warning.
5. **Registry lifecycle gaps are separate product work** (`pc2_bfb...`, `pc2_ce416...`). Rooms need a safe path-update verb; profiles need a listing view. Both are JSON-backed registries, but a generic registry framework would add indirection without removing the distinct path-ownership and lease-reservation rules.

## Recommended order and do-not-fix list

1. Bound the post-commit cursor wait first; it can delay a receipt after delivery is durable.
2. Make bare piped stdin fail loudly on a read; keep explicit `--send` as the delivery gate.
3. Fix contract provenance as one design: versioned skill/contract content, stable bridge-spec location, and a compatibility guard.
4. Take the small tooling wins (`--help`, bridge temp-path canonicalization, Porch `PYTHONPATH` instructions). Reproduce the nested mouse problem before changing Porch or Herdr.
5. Add `rooms set-path`, then a lease-aware profile listing; handle room rename only after defining how historical references and dependent state migrate.

Do not auto-send bare stdin: a typo could deliver data. Do not weaken bridge canonical-path validation to accommodate macOS temp spelling; fix the fixture. Do not change the launcher gate yet: the current test already probes for an unshimmed Cargo, and the remaining uncertainty is runtime evidence on the estate. Do not patch Porch mouse handling until the failing layer is identified. Do not revisit compact ID formatting unless a current reproduction shows a regression; the current unique-prefix marker closes the reported ambiguity.
